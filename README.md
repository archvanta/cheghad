# CHEGHAD | چقدر؟

مدیریت مالی شخصی فارسی، راست‌به‌چپ و local-first. این نسخه مرحله اول محصول است، نه تکمیل تمام مشخصات.

## اجرا

Node.js 24 و npm:

```sh
npm ci
npm run dev
```

دستورات را در ریشه مخزن اجرا کنید. مسیر برنامه `/cheghad/` است. هر وظیفه cloud محیط مستقل دارد؛ از checkout موجود استفاده کنید و بدون درخواست کاربر worktree نسازید.

## بررسی کیفیت

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` تست‌های واحد/رابط و TypeScript strict و build را اجرا می‌کند. اگر Chromium سیستم نصب است:

```sh
CHEGHAD_CHROMIUM=/usr/bin/chromium npm run test:e2e
```

در محیط محدود، برای cache از `npm ci --cache /tmp/cheghad-npm-cache` استفاده کنید. ساخت تولید با `npm run build` و اجرای آن با `npm run preview` انجام می‌شود.

## امکانات این مرحله

- داشبورد Bento و نمودار دوازده‌ماهه متصل به رویدادهای ثبت‌شده؛ تم روشن و تیره و نمایش اعداد فارسی/لاتین.
- دفتر مالی: افزودن، ویرایش، حذف با تأیید، جست‌وجو، فیلتر و ثبت پرداخت یا دریافت جزئی/کامل.
- ورود مبلغ فارسی، عربی و لاتین؛ نگهداری ریال صحیح؛ سررسید میلادی استاندارد با نمایش شمسی.
- تفکیک وجه نقد واقعی و پیش‌بینی، بدهی، ذخیره هدف و هشدار داده ناقص؛ تشخیص کسری روزانه.
- ذخیره خودکار IndexedDB، پشتیبان JSON و بازیابی اعتبارسنجی‌شده با تأیید جایگزینی.

در تنظیمات، موجودی **پیش از همه رویدادها** و ذخیره هدف را تعیین کنید. از «ثبت جدید» درآمد، هزینه یا قسط بسازید و در «دفتر مالی» ویرایش یا پرداخت آن را ثبت کنید. مبلغ خالی یعنی نامشخص؛ صفر با نامشخص متفاوت است. پرداخت اشتباه فعلاً با حذف رکورد و ثبت مجدد اصلاح می‌شود؛ Undo و اصلاح مستقل پرداخت در مراحل بعد می‌آید.

نمودار فعلاً فقط رویدادهای صریح ثبت‌شده را نشان می‌دهد؛ درآمد و هزینه خودکار تکرار نمی‌شوند. پیش‌بینی شامل درآمد مورد انتظار و تعهدات عقب‌افتاده است و وعده توان سرمایه‌گذاری قطعی نیست. کمینه روزانه ترتیب ساعتی رویدادهای هم‌روز را مدل نمی‌کند. مدیریت طلا و سناریو هنوز اضافه نشده‌اند.

## حریم خصوصی

داده واقعی از پیش بارگذاری نمی‌شود و هیچ Analytics یا سرویس خارجی داده مالی دریافت نمی‌کند. فونت نیز همراه build ارائه می‌شود. پشتیبان‌ها خصوصی‌اند؛ فایل‌های `*.private.json` و مسیر `private/` در Git نادیده گرفته می‌شوند. پاک‌شدن داده مرورگر موجب حذف اطلاعات می‌شود؛ مرتب پشتیبان بگیرید. همگام‌سازی بین دستگاه‌ها وجود ندارد.

## معماری و انتشار

[معماری](docs/ARCHITECTURE.md) و [پیشرفت مراحل](PROGRESS.md) مرجع ادامه توسعه‌اند. لایه‌های domain، database و app مستقل‌اند. قالب داده نسخه ۱ است؛ نسخه‌های ناشناخته رد می‌شوند و migration نسخه بعد باید همراه تست اضافه شود.

CI روی push و PR تست و build و دو سناریوی مرورگر را اجرا می‌کند. workflow انتشار روی push به `main` پس از موفقیت بررسی‌ها خروجی `dist` را به GitHub Pages می‌فرستد. در تنظیمات مخزن، Pages → Source را روی GitHub Actions قرار دهید. این مرحله فقط تنظیم انتشار را آماده کرده است؛ انتشار یا فعال‌بودن سایت تأیید نشده است. مسیرهای ایستا و فایل‌ها زیر `/cheghad/` هستند و صفحه‌های داخلی در URL مسیر جدیدی ایجاد نمی‌کنند تا refresh به 404 نرسد.
