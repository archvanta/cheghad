# حساب کاربری و ذخیره خصوصی

## وضعیت

کد حساب‌ها آماده و با API شبیه‌سازی‌شده و runtime محلی رسمی Workers آزموده شده است؛ این به معنی فعال‌بودن سرویس آنلاین نیست. GitHub Pages فقط صفحه ورود و دموی جدا را ارائه می‌کند تا بک‌اند فعال شود. حساب مالک یا اطلاعات مالی او در سورس، دمو یا خروجی عمومی قرار ندارد.

## معماری

- Cloudflare Worker، رابط و `/api` را روی یک مبدأ ارائه می‌کند. کوکی نشست `Secure; HttpOnly; SameSite=Strict` است و پس از هفت روز منقضی می‌شود. رمز یا توکن نشست در localStorage ذخیره نمی‌شود.
- نام کاربری مستقل است؛ ایمیل و ورود گوگل لازم نیست. نام کاربری ۳ تا ۳۲ حرف/عدد انگلیسی یا `_` و رمز ۱۲ تا ۱۲۸ کاراکتر است.
- مرورگر با PBKDF2-SHA256 و ۶۰۰هزار تکرار یک credential می‌سازد. سرور با pepper، salt تصادفی و PBKDF2 صد‌هزار تکرار، verifier جدا می‌سازد. credential مثل رمز محرمانه است؛ نباید آن را در URL، log یا Git گذاشت.
- Durable Object هر کاربر، شناسه تصادفی، verifier و هش نشست‌ها را نگهداری می‌کند. محدودیت درخواست ورود، کنترل مبدأ و CSRF برقرار است.
- دفتر و یک نسخه Undo با AES-GCM و کلید اختصاصی مشتق‌شده از کلید سرور در مخزن **خصوصی** GitHub ذخیره می‌شوند. نام فایل UUID است. این رمزگذاری سمت سرور است، نه سرتاسری.
- خواندن و نوشتن با کنترل revision و SHA فایل انجام می‌شود؛ تعارض داده را بازنویسی نمی‌کند. پاسخ خام GitHub برای فایل‌های بیش از ۱ MiB پشتیبانی می‌شود.
- حذف دفتر فعلی، تاریخچه commitهای رمز‌شده GitHub را حذف نمی‌کند. بدون کلید اصلی، دفترها قابل بازیابی نیستند.
- دمو از بانک جداگانه مرورگر با داده‌های ساختگی استفاده می‌کند و به دفتر حساب واقعی دسترسی ندارد. داده‌های قدیمی IndexedDB حذف نمی‌شوند.

## استقرار یک‌باره

۱. یک مخزن خصوصی و قابل نوشتن برای داده‌ها بسازید، مثلاً `cheghad-private-data`؛ بهتر است با README اولیه ساخته شود. توکن fine-grained با دسترسی Contents خواندن/نوشتن فقط برای همان مخزن لازم است.

۲. اعتبارنامه‌ها را فقط در Secrets محیط تنظیم کنید:

- `CLOUDFLARE_API_TOKEN`: مجوز استقرار Workers در حساب خودتان؛ قالب Edit Cloudflare Workers مناسب است.
- `GITHUB_DATA_TOKEN`: توکن محدود به مخزن داده.

متغیرهای غیرمحرمانه:

- `CLOUDFLARE_ACCOUNT_ID`
- `GITHUB_DATA_REPO`: به شکل `owner/private-repository`

۳. از ریشه پروژه اجرا کنید:

```sh
npm run deploy:accounts
```

اسکریپت ابتدا خصوصی‌بودن مخزن را بررسی می‌کند، کلیدهای سرور را یک بار در `/workspace/private-cheghad/backend-secrets.private.json` با دسترسی محدود می‌سازد، تست و build حساب را اجرا می‌کند، Worker و secrets را منتشر می‌کند و آدرس را نشان می‌دهد. برای مسیر دیگر از `CHEGHAD_SERVER_SECRET_FILE` استفاده کنید. این فایل را خارج از Git، امن پشتیبان بگیرید. اگر Worker قبلاً وجود داشته باشد و پشتیبان کلید موجود نباشد، اسکریپت متوقف می‌شود تا داده‌ها با کلید تازه ناخوانا نشوند.

رابط حساب با `VITE_ACCOUNT_API_BASE=/api` و base `/` ساخته می‌شود. قرار دادن این API روی یک مبدأ جدا از GitHub Pages، بدون انتقال رابط به همان Worker، پشتیبانی نمی‌شود؛ کوکی امن نباید به ذخیره توکن در مرورگر تبدیل شود.

۴. پس از استقرار، ساخت حساب، ورود دوباره، ذخیره دفتر، reload و جداسازی دو حساب را روی آدرس واقعی بررسی کنید. فقط بعد از موفقیت، دفتر خصوصی مالک را از فایل خارج مخزن وارد کنید. مبالغ دریافت‌نشده نباید پرداخت واقعی شوند. رمز مالک را در سورس یا فایل تنظیمات قرار ندهید.

## تست

```sh
npm run check
npm run test:e2e
npm run test:e2e:accounts
npm run test:accounts-runtime
```

تست دوم مرورگر، API حساب را شبیه‌سازی می‌کند؛ تست runtime از Durable Object و Web Crypto واقعی شبیه‌ساز Workers و GitHub شبیه‌سازی‌شده استفاده می‌کند. تماس زنده و استقرار واقعی به دسترسی سرویس‌ها نیاز دارد.

این طراحی از منابع مناسب سهمیه رایگان استفاده می‌کند؛ مصرف و محدودیت حساب Cloudflare و GitHub همچنان اعمال می‌شود. هیچ ارتقای طرح یا منبع پولی به طور خودکار ایجاد نمی‌شود.

## استقرار از داشبورد Cloudflare متصل به GitHub

Worker پروژه `cheghad` و شاخه تولید `main` است. تنظیمات اصلی در `wrangler.toml` ریشه قرار دارد. فرمان Deploy همان `npx wrangler deploy` است؛ فرمان build تنظیم‌شده در همین فایل، `npm run build:accounts` را اجرا می‌کند و `/api` و رابط را با هم منتشر می‌کند. به پیکربندی خودکار Vite نیاز نیست. اگر Build command جداگانه تعیین شده، می‌توان آن را `npm run build:accounts` قرار داد.

در Settings → Variables and Secrets این متغیر عمومی و سه Secret را تنظیم کنید:

- Text variable: `GITHUB_DATA_REPO` با نام کامل مخزن خصوصی.
- Secrets: `GITHUB_DATA_TOKEN`، `AUTH_PEPPER` و `LEDGER_ENCRYPTION_KEY`.

`CLOUDFLARE_API_TOKEN` کلید ورود کاربران برنامه نیست و جای هیچ‌کدام از این سه Secret قرار نمی‌گیرد. تنظیم `keep_vars` باعث حفظ متغیرهای داشبورد در استقرار بعدی می‌شود. کلیدهای رمزگذاری را ثابت و خارج از Git پشتیبان بگیرید. پس از تغییر تنظیمات، نسخه جدید را منتشر و ورود/ثبت‌نام را بررسی کنید.
