# CHEGHAD | چقدر؟

وب‌اپ فارسی و local-first برای درآمد، هزینه، بدهی، طلا و دلار؛ تصمیم‌ها را پیش از انجام واقعی مقایسه کنید. داده آغازین خالی است و هیچ اطلاعات مالی خصوصی در سورس قرار ندارد.

## اجرا و تست

Node.js 24 و npm، در ریشه همین مخزن:

```sh
npm ci
npm run dev
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` تست‌های مالی/رابط/IndexedDB، TypeScript strict و build تولید را اجرا می‌کند. در محیط دارای Chromium سیستم:

```sh
CHEGHAD_CHROMIUM=/usr/bin/chromium npm run test:e2e
```

برای cache در محیط محدود از `npm ci --cache /tmp/cheghad-npm-cache` استفاده کنید. مسیر برنامه `/cheghad/` است؛ تولید را با `npm run build` بسازید و با `npm run preview` بررسی کنید. هر وظیفه cloud محیط مستقل دارد؛ از checkout موجود استفاده کنید و بدون درخواست کاربر worktree نسازید.

## شروع خصوصی

اولین ورود، راهنمای شش‌مرحله‌ای ترجیحات، درآمد، هزینه، قسط، نقد/دارایی اولیه و مرور را نشان می‌دهد. مراحل اختیاری را می‌توان رد کرد؛ پیشرفت در مرورگر می‌ماند. راهنما از تنظیمات دوباره باز می‌شود. برای بازیابی، JSON خصوصی خود را انتخاب کنید؛ جایگزینی نیازمند تأیید است.

موجودی افتتاحیه، نقد **قبل از همه دریافت‌ها و پرداخت‌های ثبت‌شده** است. مانده امروز را همراه پرداخت‌های گذشته دوباره وارد نکنید. مبلغ خالی یعنی نامعلوم؛ صفر با نامعلوم متفاوت است. در تمام فرم‌های مالی واحد ورودی صریحاً **تومان** است؛ واحد نمایش نتیجه در تنظیمات ریال یا تومان است.

## درآمد و هزینه

- «ثبت جدید» یا صفحات درآمد/هزینه: افزودن، ویرایش، تاریخ شمسی یا میلادی، منبع، نوع درآمد، یادداشت و وضعیت پیش‌بینی/قطعی.
- «دفتر مالی»: ثبت دریافت یا پرداخت جزئی، تاریخچه پرداخت، برگشت پرداخت اشتباه، حذف با تأیید، فیلتر نوع/دسته/ماه و مرتب‌سازی.
- «برنامه و بودجه»: تکرار روزانه/هفتگی/ماهانه شمسی، تغییر مبلغ از تاریخ امروز یا آینده و پایان تکرار. روز ناموجود به پایان ماه کوتاه منتقل می‌شود و در ماه بعد به روز اصلی بازمی‌گردد.
- ویرایش برنامه آینده، رخدادهای قبلی را حفظ می‌کند. رخداد ویرایش یا پرداخت‌شده مستقل می‌شود. حذف یک رخداد، آن را از تولید مجدد مستثنی می‌کند.
- دسته‌بندی قابل تغییر نام، جابه‌جایی و حذف؛ سقف بودجه با پرداخت واقعی براساس تاریخ وقوع مقایسه می‌شود و دوباره از نقد کسر نمی‌شود.
- تحلیل تغییر هزینه، اثر فرضی هزینه ثابت را طی ۱، ۳، ۶ و ۱۲ ماه محاسبه می‌کند.

## بدهی و تسویه

قرارداد را با اعتباردهنده، شناسه، اصل بدهی اختیاری و مجوز مستقل پرداخت جزئی/زودهنگام بسازید. سپس اقساط دستی یا CSV/JSON را وارد کنید. داده واردشده نیازمند بررسی و تأیید است و ورود تکراری رد می‌شود. قالب CSV:

```csv
title,amountRial,dueDate
قسط عمومی,10000,2027-01-01
```

CSV ساده این قالب سه ستون دارد و ویرگول داخل عنوان را نمی‌پذیرد؛ JSON برای عنوان‌های پیچیده مناسب است. JSON آرایه‌ای از اشیای `title`، `amount` (ریال صحیح) و `dueDate` (ISO) است.

قسط فاقد پرداخت قابل لغو است. تاریخ و قرارداد آن از دفتر قابل اصلاح است. مجوز نامعلوم مانع پرداخت زود/جزئی قرارداد می‌شود. تسویه واقعی همه اقساط به مبلغ اعلام‌شده، فقط پس از تأیید شرایط و پرداخت واقعی ثبت می‌شود؛ وجه نقد و کاهش اصل بدهی جدا هستند تا تخفیف/جریمه درست لحاظ شود. برای پرداخت زودهنگام قسط خاص، همان قسط را با مجوز قرارداد پرداخت کنید. اتصال خودکار به حساب اعتباردهنده وجود ندارد.

## طلا و دلار

دارایی ۱۸/۲۴ عیار، آب‌شده، دیجیتال، سکه یا دلار آمریکا بسازید. قیمت مرجع دستی، تاریخ و اختلاف فروش را تعیین کنید. خرید و فروش جزئی، کارمزد، اجرت، مالیات و هزینه دیگر را ثبت کنید. معاملات قابل ویرایش/حذف‌اند؛ فروش بیش از موجودی یا حذف خریدی که فروش بعدی را نامعتبر می‌کند رد می‌شود.

مقدار تا شش رقم اعشار و بهای میانگین موزون محاسبه می‌شود؛ ارزش معامله با گردکردن صریح نیم‌به‌بالا به ریال ذخیره می‌شود. نقد خرید/فروش، بهای مانده، سود محقق‌شده/نشده، ارزش مرجع و ارزش پس از اختلاف فروش جدا هستند. قیمت‌ها زنده نیستند. دارایی اولیه پیش از افتتاح دفتر را صریحاً به‌عنوان موجودی اولیه ثبت کنید تا دوباره نقد کم نشود.

## آزمایشگاه تصمیم

سناریوی نقد، طلا، دلار، بدهی یا ترکیبی بسازید؛ نام، تخصیص، ذخیره، کارمزد، مسیر فرضی قیمت و خرید پلکانی ماهانه قابل ویرایش‌اند. چهار یا بیشتر سناریو قابل مقایسه، کپی و حذف هستند. مجموع تخصیص از بودجه تعیین‌شده بیشتر نمی‌شود؛ اگر بودجه از نقد واقعی بیشتر باشد، هشدار تأمین وجه و کسری نمایش داده می‌شود.

پرداخت اسمی بدهی فرضی است؛ روش مبلغ اعلام‌شده فرض می‌کند اعتباردهنده حذف همه اقساط را بپذیرد. هیچ سناریویی دفتر واقعی را تغییر نمی‌دهد. تغییر درصد قیمت، خطی طی افق اعمال می‌شود؛ قیمت دلخواه هر ماه فقط همان ماه را جایگزین می‌کند. خرید پلکانی در پایان ماه انجام می‌شود و کسری با صفر پنهان نمی‌شود. مقایسه خالص دارایی پایان با نرخ مرجع است؛ ارزش فروش پس از اختلاف نرخ هم جدا نمایش داده می‌شود.

## تقویم، پیش‌بینی و گزارش

تقویم شمسی/میلادی و جزئیات هر روز، پیش‌بینی روزانه و ماهانه ۳/۶/۱۲/۱۸/۲۴ ماه با سناریوی انتخابی، گزارش واقعی براساس تاریخ پرداخت، مقایسه سه ماه و خروجی CSV واقعی/پیش‌بینی در دسترس‌اند. چاپ مرورگر برای PDF استفاده می‌شود.

فرض پیش‌بینی: دریافت‌های مورد انتظار وصول و تعهدات پرداخت می‌شوند؛ موارد عقب‌افتاده در امروز لحاظ می‌شوند. رویدادهای هم‌روز جمع می‌شوند و ترتیب ساعتی معلوم نیست. هزینه/نرخ نامعلوم هشدار دارد و پیش‌بینی کامل محسوب نمی‌شود. قیمت فعلی جای سابقه قیمت تاریخی را نمی‌گیرد؛ گزارش واقعی معاملات از نرخ ثبت‌شده استفاده می‌کند.

## ذخیره، حریم خصوصی و معماری

اطلاعات و Undo آخرین تغییر در IndexedDB می‌مانند. تاریخچه ۱۰۰ اقدام اخیر در تنظیمات قابل مشاهده است. نوشتن اتمیک است؛ نسخه قدیمی یک پنجره نمی‌تواند داده پنجره دیگر را بازنویسی کند. هنگام تعارض، تغییرات جدید ذخیره نمی‌شوند و باید صفحه را دوباره باز کنید.

از تنظیمات JSON خصوصی بگیرید؛ حذف داده مرورگر یا استفاده از دستگاه دیگر داده‌ها را همراه نمی‌برد. پاک‌کردن همه اطلاعات، نسخه Undo را هم حذف می‌کند. فایل‌های `*.private.json` و مسیر `private/` در Git نادیده گرفته می‌شوند. Analytics، ارسال داده مالی، کلید خصوصی یا سرویس همگام‌سازی در محصول وجود ندارد. فونت وزیرمتن هم محلی ارائه می‌شود.

[معماری](docs/ARCHITECTURE.md)، [گزارش کیفیت](docs/QA.md) و [پیشرفت](PROGRESS.md) مرجع ادامه توسعه‌اند. React/TypeScript/Vite برای رابط، توابع خالص domain با ریال صحیح و Decimal برای مالی، Zod برای اعتبارسنجی و Dexie برای ذخیره استفاده می‌شوند. سند نسخه ۵، پشتیبان‌های نسخه ۱ تا ۴ را مهاجرت می‌دهد. نام کلیدهای قدیمی `goldAssets` و `goldTransactions` برای سازگاری نگه داشته شده، اما دارایی دلار نیز با نوع و واحد مستقل همان‌جا ذخیره می‌شود.

## انتشار

CI روی push/PR تست، build و مرورگر را اجرا می‌کند. workflow انتشار روی push به `main` بعد از بررسی‌ها، خروجی `dist` را به Pages می‌فرستد. پیش‌نیاز گیت‌هاب: Settings → Pages → Source = GitHub Actions. طبق قرارداد رسمی `actions/configure-pages`، فعال‌سازی اولیه با `GITHUB_TOKEN` معمولی انجام نمی‌شود؛ تنظیم باید قبلاً فعال باشد یا از دسترسی مدیریتی معتبر استفاده شود.

مسیرهای hash، refresh را زیر `/cheghad/` سالم نگه می‌دارند. لینک سایت فقط پس از تأیید deployment موفق قابل اعلام است. وضعیت واقعی انتشار در PROGRESS.md ثبت می‌شود؛ آماده‌بودن workflow به معنی انتشار نیست.
